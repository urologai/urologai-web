# ADR-WORK-001 — Agent-assisted initial corpus and update boundary

- **Status:** accepted
- **Accepted by:** project owner
- **Accepted:** 2026-09-19
- **Applies to:** all three UrologAI repositories

## Decision

UrologAI will front-load the one-time background corpus through bounded, interactive work performed with Codex and Claude Code using the project owner's existing product allowances. Evidence calls this source mode `interactive_agent_allowance`; it is neither local inference nor runtime API usage. The initial work may include the topic taxonomy, anatomy and terminology background, condition and procedure overviews, evidence/source registries, article metadata, citation mappings, glossary material, navigation, search inputs, and other non-live seed artifacts.

This bootstrap method does not make either coding agent a runtime dependency. Generated material is stored as versioned, schema-valid seed packages with stable identifiers so the later Render/API pipeline can import it once and then own surveillance, incremental updates, regeneration, verification, challenge processing, and new versions.

## Required controls

- Divide work into non-overlapping GitHub-claimed batches; one builder owns each batch.
- Claims do not expire into automatic takeover; reassignment requires an explicit handoff with branch and commit identity.
- Use the same schemas, stable IDs, source types, claim mappings, disclosures, and validation gates expected by the future canonical pipeline.
- Record source identifiers and retrieval dates, policy/schema versions, model/provider identity when available, automated checks, artifact hashes, and authorship/review status.
- Label generated material accurately as AI-generated and do not imply general human or clinician review.
- Keep patient-specific advice, raw private inputs, credentials, restricted source text, private reviewer data, and exact actionable fragments out of public repositories.
- Keep seed drafts private until the applicable schemas, licensing decision, provenance controls, verifiers, release gates, and disclosures pass; only sanitized release projections may enter `urologai-content`.
- Require an immutable build receipt and read-only Render observation for every material committed build or generation batch.
- Treat GitHub history as provenance and coordination evidence, not as the canonical live clinical database.
- Keep development build receipts distinct from the cryptographically signed production release receipts defined by later blocks.

## Rationale

The initial corpus is a large, mostly one-time workload. Using interactive product allowances reduces early API spend while the platform, gates, and update machinery are still being built. Stable schemas and provenance let that work survive the transition rather than becoming throwaway prose.

## Consequences

- Initial progress is limited by interactive-agent usage limits and should be produced in reviewable batches, not one opaque bulk dump.
- API/provider costs remain necessary for continuous operation and automated updates.
- A topic generated by one agent is not regenerated by another unless an issue explicitly requests review, comparison, or replacement.
- Any conflict with the accepted build plan, safety gates, or trust boundaries is resolved in favor of those controls.
